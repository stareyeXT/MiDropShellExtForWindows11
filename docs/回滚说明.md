# 一键回滚说明

本机当前生效的三层改动，全部可逆，互不依赖。按需要从下往上撤。

## 0. 先确认现在装了什么

```powershell
Get-AppxPackage -Name MiDropShellExt.Sparse |
  Select-Object PackageFullName, InstallLocation, SignatureKind, IsDevelopmentMode
```

预期：`MiDropShellExt.Sparse_1.0.0.0_x64__dsqz99bn8amy0`，`IsDevelopmentMode=True`。

## 1. 撤掉 sparse 包（撤新式菜单 / 共享面板 / 开始菜单磁贴）

```powershell
cd .\src\SparsePackage   # 在仓库根目录执行
powershell -NoProfile -ExecutionPolicy Bypass -File .\Unregister.ps1
```

验证已撤干净（两条都应为空/不存在）：

```powershell
$k=[Microsoft.Win32.Registry]::LocalMachine.OpenSubKey('SOFTWARE\Classes\PackagedCom\ClassIndex\{976D43D8-907F-46AF-B47F-07084C71A2F0}')
$k.GetSubKeyNames()
Get-StartApps | Where-Object { $_.Name -match '小米互传' }
```

撤完后经典菜单里的「使用小米互传发送」仍在（它走 HKCU 裸注册，不受影响）。

## 2. HKCU 裸注册（当前**未启用**，撤的时候不用管）

现在生效的只有 sparse 包一处；`HKCU` 那边没有任何我们的键（`CLSID\{504d69c0}` 覆盖已在 A/B 后删除，备份 `.backup\hkcu_CLSID_504d69c0.20261110-180826.reg`）。
经典菜单里的第 1 条由**小米管家自带的官方 DLL** 应答，第 2 条由 sparse 包应答（重复项成因见 `docs\功能对照表.md`）。

撤覆盖后做过一次点击验证：经典菜单第 1 条（官方 DLL）弹出「小米互传 · 发送」，`发送示例.txt` 显示 15B，实际 15 字节；`shellExt.log` 零新增，确认不是我们的 DLL 应答。第 2 条（我们的包）有日志、同样弹出面板。所以覆盖保持删除，不恢复。

如果想反过来让经典菜单第 1 条改用我们的 DLL（即启用裸注册），写这一处即可：

```powershell
$k='HKCU:\Software\Classes\CLSID\{504d69c0-cb52-48df-b5b5-7161829fabc8}\InprocServer32'
New-Item -Force -Path $k | Out-Null
Set-ItemProperty -Path $k -Name '(Default)' -Value "$env:LOCALAPPDATA\MiDropHelper\MiDropShellExt.dll"
Set-ItemProperty -Path $k -Name 'ThreadingModel' -Value 'Apartment'
# 重启 explorer 后生效
```

撤掉只需删这一棵树（删前导出备份）：

```powershell
reg export "HKCU\SOFTWARE\Classes\CLSID\{504d69c0-cb52-48df-b5b5-7161829fabc8}" .backup\clsid-504d69c0-hkcu.reg /y
[Microsoft.Win32.Registry]::CurrentUser.DeleteSubKeyTree('SOFTWARE\Classes\CLSID\{504d69c0-cb52-48df-b5b5-7161829fabc8}', $false)
```

注意：`reg.exe` 对含 `{}` 的路径会报 `Invalid syntax`，删的时候用 .NET Registry API；
`Test-Path "HKLM:\SOFTWARE\Classes\*\shell\..."` 会因 `*` 通配扫全表卡死几分钟，别用。

## 3. 还原 shell 扩展 DLL（回到官方 6.x 自带那份）

`C:\Program Files\MI\XiaomiPCManager\6.0.2.30\MiSmartShare\MiDropShellExt.dll`（76888 字节）**本 Bot 从未改动**，系统目录零写入。

我们只写过 `%LOCALAPPDATA%\MiDropHelper\MiDropShellExt.dll`（自己的副本）。
要回到装扩展之前的状态，把它删掉即可（或覆盖回备份）：

```powershell
Remove-Item "$env:LOCALAPPDATA\MiDropHelper\MiDropShellExt.dll" -Force
```

小米电脑管家自带的右键项（官方那一份）始终在自己的注册表里，从未被我们改过。

## 4. 日志与残留

- 日志：`%LOCALAPPDATA%\MiDropHelper\shellExt.log`
- 文件清单缓存：`%LOCALAPPDATA%\MiDropHelper\ShareFiles\`（key 用完即删，可整个删）
- 包 VFS：`%LOCALAPPDATA%\Packages\MiDropShellExt.Sparse_dsqz99bn8amy0\`（注销包后可删）

## 恢复成本

第 1 步约 5 秒；第 2 步约 10 秒；两步都做完即回到「只有官方自带右键项」的原状。

## 维护注意（重建时必须做）

**DLL 有两份，必须同步**，否则新式菜单加载的还是旧版：

| 位置 | 谁在用 |
|---|---|
| `src\SparsePackage\MiDropShellExt.dll` | 新式菜单、共享面板、开始菜单磁贴（sparse 包的 `com:SurrogateServer` 按包目录找 DLL） |
| `%LOCALAPPDATA%\MiDropHelper\MiDropShellExt.dll` | 当前**没有**人用它（HKCU 覆盖未启用）；只有在启用「让经典菜单第 1 条走我们的 DLL」时才需要，见第 2 步 |

一份 `dotnet publish` 出来的 DLL 要同时铺到这两个位置（后者建议仍然铺，便于随时切），`Register.ps1` 不会替你同步包目录那份。
包根目录的 `MiDrop.Helper.exe` 只服务开始菜单磁贴（`XiaomiApp` 激活），不参与右键发送；
右键发送用的 helper 永远是 `%LOCALAPPDATA%\MiDropHelper\MiDrop.Helper.exe`（原因见 `docs\功能对照表.md`）。
